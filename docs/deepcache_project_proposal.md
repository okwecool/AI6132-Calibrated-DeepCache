## 1. 推荐立项范围

推荐题目：**低资源图像生成中扩散特征缓存策略的比较与校准优化**。

英文：**A Comparative Study of Diffusion Feature Caching with Calibration-Based Refresh Scheduling**。

核心问题：**给定相同的完整 U-Net 刷新次数，能否把刷新安排在更有价值的去噪步骤，使生成结果更接近无缓存基准，同时保持文本对齐和速度？**

以 SD1.5 文生图为任务，主实验使用确定性的 DDIM（eta=0）和固定采样步数；比较原始 DeepCache、原论文非均匀策略、校准得到的刷新策略，再加入无缓存 DPM-Solver++ 作为另一类已有加速方法。这样同时包含方法比较、组件分析、自己的修改、可视化和局限讨论。

无需从头训练生成模型，也不把 SDXL、视频、多条件 ControlNet 或多个底模作为最低交付范围。

## 2. DeepCache 原理与必须澄清的贡献边界

普通扩散生成反复执行完整 U-Net。DeepCache 利用相邻去噪步骤中高层特征的冗余：刷新步骤执行完整计算并保存特征；复用步骤读取缓存并执行部分网络。它保留扩散迭代步数，减少的是部分步骤中的网络计算。

示意，F 表示完整刷新，R 表示复用：

```text
普通采样：     F F F F F F F F F F F F
间隔为 3：    F R R F R R F R R F R R
待优化策略：  在同样 4 个 F 的预算内重新安排位置
```

三个重要边界：

1. 原论文已经提出 **Non-uniform 1:N Inference**。所以“前后少缓存、中间多缓存”之类固定分段规则，应作为比较或复现，不应直接包装成新的非均匀缓存概念。
2. 自适应缓存也已有 DiCache 等研究。本项目的贡献定位为 U-Net/SD1.5 场景的校准实现、受控比较和实验分析，不预先承诺算法新颖性。
3. “无需训练”不等于“没有额外成本”：校准、特征采集、缓存内存和策略搜索都要记录。生成模型权重保持不变。

来源：[DeepCache 论文 §3.3、附录 B/C](https://arxiv.org/html/2312.00858v2)、[官方仓库](https://github.com/horseee/DeepCache)、[DiCache 官方仓库](https://github.com/Bujiazi/DiCache)。

## 3. 把工作分成三个层次

### 层次一：必须完成的复现与评测框架

- SD1.5，512×512，FP16，batch=1。
- 固定底模、VAE、scheduler 配置、提示词、初始 latent、CFG 和推理精度。
- 跑通无缓存与官方 DeepCache，验证能完整刷新/复用且无缓存状态串图。
- 扫描缓存间隔 2/3/5；先固定一个 cache branch。
- 输出每张图、配置、时间、显存、刷新步骤列表。

检查失败时先解决环境或 hook 兼容性，不展开更复杂策略。

### 层次二：主改动——基于校准的固定预算刷新策略

用小规模校准集估计哪些阶段的缓存特征变化大，在固定完整刷新次数 B 下，离线生成一份刷新步骤列表。正式推理只查表，因此避免在线检测引入额外网络计算。

例如，总步数 T=50：

- 统一间隔 3 对应 B=17 个刷新步骤。
- 原论文非均匀策略也设置为 B=17。
- 校准策略同样严格使用 B=17，并包含第 0 步。

不能通过多刷新几次来声称校准策略质量更好。固定分支、固定步数、固定 B 时，预期主要改变刷新位置；最终仍以实际时间和显存核实预算。

**一个具体、可实现的校准方法：**

1. 在约 20 个校准提示词上执行完整无缓存 DDIM 轨迹，记录拟缓存边界的代表性特征。CFG 两个分支分开度量后汇总，避免相互抵消。只保存所需边界特征到 CPU，或流式累计统计，避免存完整 U-Net 激活。
2. 对每一段候选缓存区间 [a,b)，估计一直复用第 a 步特征时的漂移代价：

   `C(a,b) = average_over_calibration_samples(sum_{i=a}^{b-1} relative_distance(g_i, g_a))`

   其中 `relative_distance(g_i,g_a) = mean(abs(g_i-g_a)) / (mean(abs(g_i)) + epsilon)`；g 是选定的实际缓存边界特征。若使用多个张量，需要先归一化，不能让张量大小直接决定权重。
3. 将 50 个步骤划分成 B 个连续区间，用小型动态规划寻找区间代价之和较小的刷新列表。保留最大间隔约束，避免集中刷新后留下极长复用段。该优化只保证代理代价较小，不保证最终图像质量最优。
4. 在独立验证集上实际生成图片，检查该代理优化是否改善最终效果；冻结策略后再用测试集评价。

**为什么必须做第 4 步：** 无缓存轨迹上的特征漂移只是代理；缓存推理会改变后续 latent，真实误差不一定按代理累计。代理相关性不足时，应报告这个结果，转为对少量候选刷新列表做验证集直接搜索，而不是继续声称“误差最优”。

原论文非均匀基线的 center/power 也应使用同一验证集和可比的搜索预算，避免让自己的方法获得更多调参机会。整数化后检查步骤数、唯一性、顺序和首步刷新。

### 层次三：有余力才做的扩展——按输入动态刷新

在每步本来就会执行的浅层计算处取特征，比较当前特征与最近一次完整刷新时的特征。可以同时考虑相邻步变化、距上次刷新的步数和采样阶段。

```text
无有效缓存 → 完整刷新
达到最大允许缓存年龄 → 完整刷新
浅层漂移超过阈值 → 完整刷新
否则 → 复用缓存
```

这只是设计草案，有两个前置条件：

- 信号必须在决定跳过深层计算之前获得，不能先执行完整 U-Net 再决定“刚才是否应该缓存”。
- 先在校准数据检查浅层漂移与缓存误差是否相关；不要默认相关。少量离线诊断可以在同一个 latent 输入上分别运行完整路径和缓存路径估计误差，额外完整计算不计为正式在线算法的一部分，相关成本单独报告。

动态刷新次数通常不固定，应通过阈值扫出质量—延迟曲线，再与固定预算方法比较。不要只用一个更慢的动态配置对比一个更快的静态配置。

## 4. 需要修改哪些代码

官方主要入口：[DeepCache/extension/deepcache.py](https://github.com/horseee/DeepCache/blob/master/DeepCache/extension/deepcache.py)。

| 入口 | 官方作用 | 计划改动 |
|---|---|---|
| `set_params()` | 设置 interval、branch 等参数 | 增加策略配置与明确的 `refresh_steps` |
| `wrap_unet_forward()` | 标记当前去噪步骤 | 每个实际 U-Net 调用开始时确定一次是否刷新，并记录步骤索引 |
| `is_skip_step()` | 综合步骤和模块位置判断是否跳过 | 使用本步统一的刷新决定，保留原来的模块边界判断 |
| `wrap_block_forward()` | 读取/更新缓存 | 记录缓存命中/刷新；初版保持数据流不变 |
| `reset_states()` | 清空缓存状态 | 每张图片/每次生成开始时重置；保证异常后恢复 hook |

官方非均匀刷新参考：[DeepCache/sd/pipeline_stable_diffusion.py](https://github.com/horseee/DeepCache/blob/master/DeepCache/sd/pipeline_stable_diffusion.py) 中的 `interval_seq`、`center` 和 `pow` 相关逻辑。建议迁移刷新列表生成逻辑到同一个 helper，而不是同时维护两个旧版 pipeline，以减少环境差异。

实现注意事项：

- 刷新决定以一次 U-Net forward 为单位，全体模块共享，不能在每个 block 中分别改变计数。
- 显式记录调用序号，不能默认 scheduler timestep 总是唯一，也不能把 scheduler step、U-Net 调用次数、CFG 批次数混为一谈。
- 固定缓存分支作为主实验。若运行时切换 branch，会改变缓存有效性，需要强制完整刷新及缓存失效管理，初版不做。
- 按图重置缓存、按方法使用相同初始 latent；只设相同 seed 但复用已前进的随机数生成器不够可靠。
- 保留原版策略开关，确保能够直接比较官方逻辑与修改后的逻辑。

## 5. 数据与实验规模

推荐使用 [COCO 验证集及 caption](https://cocodataset.org/#download)。每张图固定选一条 caption，按图像 ID 划分，避免同图不同 caption 跨集合。

| 集合 | 初始建议规模 | 用途 |
|---|---|---|
| 排错集 | 5–10 条提示词 | 检查环境、缓存、显存、计时 |
| 校准集 | 20 条提示词 | 特征统计与刷新列表生成 |
| 验证集 | 20 条提示词 | 选择策略参数与基线参数 |
| 测试集 | 100 条提示词 × 2 个固定种子 | 冻结配置后的主实验 |

在测试集可以按单主体、多主体、复杂场景做分组分析，但不能在看完结果后只选择有利类别展示。复杂类型最好在生成前制定标注规则。

先完成 50 步下的一组 B=17 比较，再决定是否增加 B=10 或 20 步的迁移实验。固定预算策略迁移到不同总步数/solver 时，不保证直接有效；应区分“原配置直接迁移”和“重新校准”。

## 6. 最小实验矩阵

| 组别 | 方法 | 作用 |
|---|---|---|
| R | DDIM 50 步、无缓存 | 参考输出与耗时 |
| S | 无缓存 DPM-Solver++，10/20/30 步在验证集选取 | 比较减少采样步数这一已有加速路线 |
| U | DDIM 50 步、DeepCache 统一刷新，B=17 | 缓存基线 |
| N | DDIM 50 步、DeepCache 原论文非均匀刷新，B=17 | 防止把已知策略当改进 |
| C | DDIM 50 步、校准刷新，B=17 | 自己的主修改 |

在上述主矩阵之后，有针对性地增加：

- U/N/C 的 B=10，用于观察更激进缓存时的表现。
- 固定 B 的少量随机刷新列表，排除任意扰动也有同样收益的可能。
- 两个有代表性的 cache branch，而非把所有 branch 与所有参数做笛卡尔积。
- 若实现动态方法，加入阈值曲线；若未实现，不影响主任务闭环。

组 S 与 R 的 sampler 不同，只用于方法整体效率比较。评价缓存对图像的近似偏差时，U/N/C 统一对照组 R；若给 DPM-Solver++ 叠加缓存，需另设同 solver 的无缓存参考。

## 7. 指标、图表与公平性

**至少报告四类结果：**

1. **实际效率：** 端到端单图生成耗时、U-Net 阶段耗时、峰值 allocated/reserved 显存、完整刷新次数及总调用次数。预热后计时，CUDA 同步，记录多次运行波动；生成图像保存与 CLIP 评价不混入推理计时。固定供电/功耗条件，避免笔记本热状态差异。
2. **近似偏差：** 相同提示词、相同 latent 下，与无缓存 DDIM 输出比较 LPIPS；PSNR/SSIM 可作补充。这里衡量的是偏离参考输出多少，不是直接评价真实感。
3. **生成能力：** 固定 CLIP 模型与预处理计算文本对齐；配合匿名配对人工比较、失败率和样例。COCO 原图不是该随机生成结果的像素级真值，不做逐图 PSNR 真值评测。
4. **校准开销：** 完整特征采集时间、搜索时间、所需内存。推理收益为每张节省 Δt 时，报告粗略摊销图数 `calibration_time / Δt`，若 Δt<=0 则无收益可摊销。

以实际时间为横轴、文本对齐/LPIPS 为纵轴画曲线，不能仅凭相同 B 宣称端到端速度完全相同。对于小测试集，FID 可以不列主指标；若计算，明确是小样本探索结果，不与论文大样本 FID 直接比较。

推荐交付图表：

- 方法流程图：完整刷新与复用路径。
- 质量—延迟散点图或曲线：包含少步 sampler 基线。
- 校准代价/特征漂移随步骤变化曲线，叠加各策略刷新位置。
- U/N/C 同提示词同种子的横向样例，包含失败案例。
- 消融表：校准策略与随机/统一/论文非均匀策略，及 B=17/B=10。

## 8. 8GB 实施顺序与停止条件

第一天先完成本机验证：支持 Blackwell 的 PyTorch 构建、可取得的 SD1.5 权重、无缓存出图、官方缓存出图、10 个样本计时。尚不指定未验证的安装组合，不照抄旧仓库的 PyTorch 1.x 环境。

优先使用单模型 FP16、batch=1，必要时 VAE slicing/tiling。CLIP/LPIPS 评价与生成分开运行；不要让评价模型同时占用显存。缓存张量本身可能使显存上升。如果需要 CPU offload，则验证与缓存 hook 的兼容性，并将同样配置用于各组公平计时。

后续建议：

- 第 2–3 天：固定环境和数据，完成 U/N/S 基线及少量间隔扫描。
- 第 4–5 天：实现校准与列表策略，做验证集比较。
- 第 6–7 天：冻结设置，完成测试和核心消融；有时间才做动态扩展。
- 第 8–9 天：图表、报告、失败分析与代码整理。
- 第 10 天：核对贡献说明、提交文件及 NTULearn 截止时刻。

上述为建议的工作日安排，实际按首次吞吐测量调整。总实验时间用 `各配置图数 × 实测单图耗时` 估算，不能预先引用论文的硬件速度作承诺。

如果校准策略没有优于非均匀基线，也可完成一份扎实的技术综述与实验报告：说明代理误差与最终质量的关系、在哪些预算下校准失效、缓存与少步 sampler 的边界。作业评分强调深入比较与分析，不要求必须得到正向改进。

## 9. 建议代码组织与报告结构

以下是建议结构，尚未创建实现：

```text
configs/                  固定实验配置
src/cache_policy.py       uniform / original_nonuniform / calibrated
src/deepcache_helper.py   接入官方缓存逻辑并添加日志
scripts/generate.py       统一推理与计时
scripts/calibrate.py      特征统计与刷新列表生成
scripts/evaluate.py       图像/文本评价
scripts/plot_results.py   曲线和横向样例
manifests/                数据划分与种子清单，不包含图片
results/                  本机结果，提交时按要求整理
```

报告按作业指定结构写：Introduction（低资源效率问题）→ Methods（sampler、DeepCache、原论文非均匀、校准策略）→ Experiments and Analysis（数据、预算、主结果、消融、失败与开销）→ Conclusion（结论及局限）。

保留官方代码许可证及归属，清楚区分复现部分和自己的修改。提交时准备报告、成员贡献 PDF 和源代码 ZIP，不打包模型或数据集。
